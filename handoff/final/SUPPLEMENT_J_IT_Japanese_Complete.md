## J10 — Code Review Language (in Japanese)

When participating in Japanese code reviews, these phrases are essential:

### Reviewer Comments (レビュアーのコメント)

| Japanese phrase | Meaning | Formality |
|----------------|---------|-----------|
| LGTMです！ | Looks good to me! | Casual |
| 承認します | I approve | Formal |
| 指摘があります | I have some comments | Neutral |
| ご確認いただけますか | Could you check this? | Polite |
| 以下のような修正をお願いします | Please make the following modifications | Formal |
| この部分の意図を教えていただけますか | Could you explain the intent of this part? | Polite |
| 〜について相談させていただきたいです | I'd like to discuss ~ | Formal |
| ここはネーミングを変えた方が良いかもしれません | The naming here might be better changed | Suggestion |
| テストが不足している気がします | I feel tests are insufficient | Soft opinion |
| パフォーマンスに問題がある可能性があります | There may be a performance issue | Warning |
| セキュリティ上のリスクがあります | There is a security risk | Alert |
| マジックナンバーは定数にしてください | Please make magic numbers into constants | Request |
| コメントを追加してください | Please add comments | Request |
| DRY原則に反しています | This violates the DRY principle | Critique |
| 単一責任の原則を意識してください | Please be mindful of the SRP | Reminder |
| Nitについてです（細かい点ですが）| This is a nit (minor point) | Soft |

| Japanese phrase | Meaning |
|----------------|---------|
| 修正しました | I've made the fix |
| ご指摘ありがとうございます | Thank you for pointing that out |

| 別のアプローチも検討しましたが、～ | I also considered another approach, but ~ |

## J29 — Scenario 1: First Day at a Japanese Tech Company

**あなた（新入り）とチームリーダーの会話:**

> リーダー：ようこそ。今日からよろしくお願いします。まず開発環境のセットアップから始めましょうか。
> あなた：よろしくお願いします。セットアップに必要なものはありますか？
> リーダー：READMEに手順が書いてあるので、まずそれを見てください。詰まったら気軽に聞いてください。
> あなた：わかりました。開発環境はDockerを使いますか？
> リーダー：そうです。Docker ComposeでローカルでDBも立ち上げられます。あと、Slackでチャンネルに入ってもらえますか？#general と #dev-team が主なチャンネルです。
> あなた：はい。GitHubのアクセス権限も必要ですか？
> リーダー：あ、そうですね。アカウント名を教えてください。招待します。ブランチ戦略はGit Flowを使っていて、PRは必ず1名以上のレビューが必要です。
> あなた：わかりました。コーディング規約はどこかにまとまっていますか？
> リーダー：Confluenceにあります。リンクをSlackで送ります。

## J30 — Scenario 2: Bug Triage Meeting

> PM：先ほど本番でエラーが多発しているという報告がありました。状況を教えてもらえますか。
> エンジニアA：はい、午後3時ごろから〇〇のAPIが500エラーを返し始めています。エラーレートが通常の0.1%から10%に跳ね上がっています。
> PM：原因は特定できていますか？
> エンジニアA：まだ調査中ですが、デプロイとタイミングが一致しています。ロールバックを検討しています。
> PM：ユーザー影響はどの程度ですか？
> エンジニアA：〇〇機能を利用しているユーザーの約10%が影響を受けています。
> PM：わかりました。まずロールバックを実施してください。その後、根本原因の調査をお願いします。ポストモーテムは明日の午前中にお願いします。
> エンジニアA：了解です。今すぐロールバックします。完了したらSlackで報告します。

## J31 — Scenario 3: Technical Interview (技術面接)

> 面接官：では、最近取り組んだ技術的に難しかった問題を教えてください。
> 応募者：はい。前職で大量のデータを処理するバッチ処理システムのパフォーマンス改善に取り組みました。処理時間が6時間かかっていたのを、1時間以内に短縮する必要がありました。
> 面接官：どのようなアプローチを取りましたか？
> 応募者：まずボトルネックを特定するために、プロファイリングを実施しました。その結果、DBのクエリが全体の80%を占めていることがわかりました。インデックスの最適化と、N+1問題の解消、さらにバッチサイズの調整で最終的に50分まで短縮できました。
> 面接官：N+1問題について、もう少し詳しく説明してもらえますか？
> 応募者：はい。N+1問題とは、1件のデータを取得するクエリの後に、関連データをN件取得するためにN回のクエリが発行される問題です。JOINやEager LoadingでSQLを最適化することで解決しました。
